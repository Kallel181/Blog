import sys

# Rotate right: 0b1001 --> 0b1100
ror = lambda val, r_bits, max_bits: \
    ((val & (2**max_bits-1)) >> r_bits%max_bits) | \
    (val << (max_bits-(r_bits%max_bits)) & (2**max_bits-1))

max_bits = 32

input = int(raw_input("Enter the value you want to check: "))

print()
for n in xrange(1, 256):

        rotated = ror(n, i, max_bits)

        if(rotated == input):
            print("The number %i can be used as a valid immediate number." % input)

            print()
            sys.exit()

else:
    print("Sorry, %i cannot be used as an immediate number and has to be split." % input)

This is script is perfectly valid, however, there is a clever way for finding this value (255 times better to be exact XD).

What is an Immediate value on ARM?

ARM instruction are 32bit long (Thumb mode is an alternative operating state and uses 16bit instructions, but I will not cover them here, because I didn't get to that part yet), those 32 bits are filled with the mnemonic, conditional, destination register, operands and other sort of necessaries parts, in the end, there are only 12 bits left for Immediate values, which are values that are going to be used be the actual instruction in some way.

ARM architecture instead of making a 12bit long integer instead splits this number into a 8bit number(n) and a 4bit rotation filed(r).

The actual Immediate value (v) is given by the formula: v = n ror 2*r.

With this formula we know, for example, that 256 is a valid immediate because we can express 256 as the following expression: 256 = 1 ror 24.

The Valid Candidate

The actual clever way for checking if a value is a valid immediate value for ARM is by doing a left rotation (yes a left rotation) to find a candidate, if this candidate can be represented in 8 bits then we have a match.

Rotating to the right an x amount of times and following that with a left rotation by the same x amount we will be back at the start. (here I'm making a slight abuse of mathematics notation for the sake of clarity, but the calculation remains perfectly valid)

In the end we get that n will be equal to v rotated to the left by 2r, but there is a catch!!

The number n have a hard constraint, it needs to be a 8bit number, so that n on the new expression it is not your final answer, it's just a candidate, it needs to be tested to ensure that it is a 8bit number!

So your new optimized algorithm need to be a loop just on the values of 2r, generating candidates with a left rotation, if a given candidate is a 8bit number we have found a valid solution, if in the end of the loop we couldn't find a valid candidate that means that the immediate value (v) can't be represented as an ARM immediate value.

Here is a python script for that algorithm:

def rol(val, r_bits, max_bits=32):
    r_bits %= max_bits
    
    return ((val << r_bits) | (val >> (max_bits - r_bits))) & (2**max_bits - 1)

def is_arm_immediate(value):
    for rot in range(0, 32, 2):
        
        candidate = rol(value, rot)
        
        if candidate <= 0xFF:
            return True, candidate, rot

    return False, None, None

if __name__ == "__main__":
    value = int(input("Enter Value: "))

    ok, candidate, rot = is_arm_immediate(value)

    if ok:
        print(f"{value} can be represented as: {candidate} ror {rot}")
    else:
        print(f"{value} can't be represented as an ARM immediate value.")
