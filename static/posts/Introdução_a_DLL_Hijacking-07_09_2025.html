Introdução a DLL Hijacking

2025-09-07 — privilege_escalationDLLWindowslateral_movementpersistancedefence_evasion

DLL Hijacking consiste em criar DLLs arbitrarias e posicioná-las de forma que essas DLL sejam executadas no lugar de DLLs legitimas. Essa técnica pode ser usada por agentes mal-intencionados para escalar privilégios ou ainda criar uma persistência em um sistema. No artigo é detalhada a definição dos métodos de DLL Hijacking e também e mostrado alguns exemplos práticos de duas técnicas.

O que é uma DLL?

DLL é uma sigla para Dynamic Linked Library, esses arquivos contem códigos com funcionalidades variadas que podem ser compartilhados e executados por diversos programas. Vamos ver um exemplo:

Imagine que esteja criando um programa, e precisa que esse programa exiba uma janela separada com uma mensagem de erro, por exemplo, tradicionalmente, você precisaria criar um código para essa janela, definir seu comportamento, posição na tela, quais botões estariam presentes, qual mensagem teria que aparecer. Porem, podemos fazer uso da API do Windows e das inúmeras DLL que estão presentes no ambiente Windows, nesse caso poderíamos fazer uso da função MessageBox para criar a janela de erro que precisamos para nosso programa.

A principal vantagem de se usar DLLs nesse exemplo é não só economizamos tempo por não precisar criar a lógica e aparência de uma janela de erro totalmente do zero, mas também, economizamos espaço dentro do nosso programa, usando algo que já está disponível no ambiente Windows por padrão.

Como o Windows carrega DLLs

Antes de qualquer coisa é importante entendermos como o Windows e o programas nesse ambiente carregam DLLs. Para observamos na prática como isso funciona podemos uma ferramenta que podemos usar para observar esse comportamento é o Process Monitor, uma ferramenta de monitoramento do Windows que mostra em tempo real a atividade do sistema de arquivos, registo, processos e threads.

Para esse exemplo, vamos usar o programa Dism.exe, instalado por padrão em máquinas Windows, vamos criar uma cópia secundaria em outro local e iniciar o programa com o Process Monitor ativo para verificarmos quais DLLs o programa tenta carregar.

Por que fazer uma cópia local do Dism.exe e por que escolhemos o Dism.exe? Primeiro, esse exemplo poderia funcionar com muitas outras opções de programas, desde que, o programa use DLLs. Escolhi o Dism.exe pois é um exemplo que podemos encontrar no vídeo de Jhon Hammond, mas poderia ser qualquer outro programa.

Fazemos uma cópia local para podermos fazer a inserção de uma DLL arbitraria no futuro. Como o programa está localizado originalmente na pasta System32 não podemos de forma simples inserir ou substituir uma DLL nesse diretório.

A partir da verificação que fizemos no Process Monitor, podemos ver que o programa fez uma busca de diversas DLLs em diversos diretórios. Esses diretórios de busca são previstos na documentação da Microsoft, onde estão descritos os diretórios de busca padrão para as DLLs, a ordem geral de busca é mostrada na imagem abaixo:

Como podemos observar, programas possuem uma extensiva ordem de busca que envolvem uma série de mecanismos e etapas diferentes.

Com isso podemos formular a seguinte pergunta: "E se substituirmos uma DLL legítima em uma dessas etapas de busca por uma DLL arbitraria?". Isso é o que chamamos de DLL Hijacking.

O que é DLL Hijacking?

DLL Hijacking consiste em inserir uma DLL arbitraria, geralmente contento código malicioso, no lugar de uma DLL legitima.

Como DLL hijacking funciona?

Uma aplicação Windows usa o protocolo de busca de DLLs para carregar uma DLL. Dessa forma, podemos tirar vantagem de diretórios onde temos acesso à escrita para inserir uma DLL ou modificar de alguma forma a busca para levar a uma DLL maliciosa. De acordo com MITRE ATT&CK existem as seguintes possibilidades para DLL Hijacking.

DLL Search Order Hijacking

Essa técnica consiste em criar uma DLL arbitraria em uma localização que seja carregada antes de uma DLL legitima, dessa forma, a DLL legitima é ignorada e a DLL arbitraria é executada. Isso se faz possível a partir do protocolo de ordem de busca de DLLs do Windows.

DLL Redirection

Essa técnica consiste em mudar a ordem de busca a partir de uma DLL redirection. Pode ser feita a partir da criação de um arquivo de redirecionamento ou na alteração de parâmetros no Registro do Windows, essa mudança faz com que DLLs legitimas sejam ignoradas e DLLs arbitrarias em diretórios alternativos sejam executadas.

Phantom DLL Hijacking

Essa técnica consiste em criar uma DLL arbitraria em no lugar de uma DLL que deveria ter sido carregada por algum programa, mas que não foi encontrada ou que não existia previamente.

DLL Substitution

Assim como Phantom DLL, essa técnica consiste em colocar uma DLL arbitraria em lugar de uma DLL legitima, porem, nessa técnica, fazemos uma substituição de uma DLL legitima que de fato existia previamente.

DLL Sideloading

Essa técnica consiste em forçar um programa a carregar uma DLL arbitraria que ele anteriormente não carregaria, alterando diretamente seu comportamento, dessa forma, é possível mascarar uma atividade suspeita com uma aplicação que poderia estar previamente instalada e considerada confiável. Ou ainda, e possível distribuir uma aplicação que pareça confiável mas que carrega com ela uma DLL maliciosa.

DLL Hijacking na prática

Vamos agora ver duas aplicações praticas de DLL Hijacking, uma delas usando Dism.exe e a última usando um aplicativo de update do Notepad++.

Phantom DLL Hijacking com Dism.exe e DismCore.dll

Vamos voltar ao exemplo do Dism.exe e fazer uma inserção de uma DLL arbitraria. Durante nossa análise inicial observarmos que o Dism.exe procurar por uma DLL chamada DismCode.dll no mesmo diretorio de onde está localizado o programa, mas a DLL não foi encontrada.

Podemos fazer o que a unit42 chama de Phantom DLL Loading, que consiste em inserir uma DLL arbitraria em uma localização onde há uma DLL que não existe ou que não esteja presente. No nosso caso temos que criar uma DLL no caminho C:\Users\Kallel\Desktop\DLL chamada DismCode.dll.

Porque usar DismCore.dll? Mesmo que pareça existir uma série de DLLs as quais podemos fazer uma substituição, nem todas são executas da forma que queremos. Podemos encontrar uma lista de DLLs de programas vulneráveis no seguinte site: https://hijacklibs.net

Informações especificas sobre a DLL DismCore.dll podem ser encontradas no seguinte link: https://hijacklibs.net/entries/microsoft/built-in/dismcore.html

Vamos usar para esse exemplo o seguinte código para a DLL:

#include <windows.h>

BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved){
  switch(ul_reason_for_call){
    case DLL_PROCESS_ATTACH:
      MessageBox(NULL,"Hello","Hello", MB_OK | MB_ICONINFORMATION);
      break;

    case DLL_PROCESS_DETACH:
      break;

    case DLL_THREAD_ATTACH:
      break;

    case DLL_THREAD_DETACH:
      break;
  } 

  return TRUE;
}

Essa DLL simples faz com que assim que for acoplada em um processo ela exibe uma MessageBox (usando a API do Windows). Tudo que temos que fazer é compilar essa DLL usando o native tools do Visual Studio com o comando cl /LD test.c user32.lib e renomear o arquivo para DismCore.dll e colocar esse arquivo no mesmo diretório do Dism.exe, depois disso, assim que executarmos o Dism.exe uma caixa de mensagem do Windows deve aparecer.

DLL Sideloading com libcurl.dll, GUP.exe e Notepad++

Vamos agora ver outro exemplo de DLL Hijacking, nesse exemplo, vamos analisar um programa auxiliar instalado junto do Notepad++, o GUP.exe.

Mais informações sobre o ataque a essa DLL especifica podem ser encontrado no seguinte link: https://hijacklibs.net/entries/3rd_party/curl/libcurl.html

Primeiramente é importante entendermos o que é o GUP.exe e o que ele faz. O GUP.exe é um updater genérico, no caso do Notepad++ podemos encontrá-lo no diretório C:\Program Files\Notepad++\updater, como o nome diz, ele é responsável por fazer update no Notepad++.

Podemos assim como no exemplo anterior, criar alguns filtros usando o Process Monitor para verificar quais DLLs esse programa tenta acessar, nesse caso vamos fazer as seguintes regas de filtros: - Process Name is GUP.exe (Include) - Operation is CreateFile (Include) - Path ends with .dll (Include) - Path contains C:\Windows (Exclude)

Podemos notar que a DLL que está presente na pasta do GUP.exe chamada libcurl.dll é usada pelo programa, algo que podemos fazer é sobrescrever essa DLL com uma DLL arbitraria, vamos usar o mesmo código anterior para substituir essa DLL:

#include <windows.h>

BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved){

  switch(ul_reason_for_call){
    case DLL_PROCESS_ATTACH:
      MessageBox(NULL,"Hello","Hello", MB_OK | MB_ICONINFORMATION);
      break;

    case DLL_PROCESS_DETACH:
      break;

    case DLL_THREAD_ATTACH:
      break;

    case DLL_THREAD_DETACH:
      break;
  } 

  return TRUE;
}

Vamos compilar esse código como uma DLL usando o native tools do Visual Studio com o comando cl /LD test.c user32.lib e renomea-la para libcurl.dll e substituir a original. Ao fazermos isso, podemos notar que não obtivemos o resultado esperado:

O GUP.exe nos retorna uma mensagem de erro. Isso se deve ao fato de que a nossa DLL não possui alguma funcionalidade esperada pelo programa, dessa forma não conseguimos atingir a seção do switch(ul_reason_for_call) da nossa DLL arbitraria.

Riscos e prevenção de DLL Hijacking

DLL Hijacking é uma técnica que permite que aplicações confiáveis executem códigos arbitrários, dessa forma, é possível esconder operações maliciosas sobre aplicativos confiáveis. Isso pode ser usado não só para criar uma persistência a um sistema, mas também pode ser usado para escalar privilégios em um sistema.

Mitigações, segundo MITRE ATT&CK incluem fazer auditorias, auxiliar desenvolvedores a incluir verificações em hash de DLLs utilizadas, prevenção execução de DLL não confiaveis e verificação de inserções de DLLs.

Adicionalmente hijacklibs.net fornece exemplos de regras Sigma para sistemas SIEM.
